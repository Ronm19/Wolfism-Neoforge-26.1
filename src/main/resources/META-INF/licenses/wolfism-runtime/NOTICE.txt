Replacing or rebuilding an LGPL library

The LGPL libraries remain separate jar files. Extract the relevant source ZIP with
an ordinary ZIP tool and build the upstream project with its included Gradle wrapper
and required JDK. TerraBlender derives its version from Git tags: a Git checkout at
the recorded commit with tags fetched preserves the release version calculation;
the complete source archive also contains its build scripts.

An interface-compatible modified LGPL jar can replace its corresponding entry in
META-INF/jarjar in a copy of the Wolfism jar using any ZIP tool. Preserve its manifest,
mod identifier, and nested dependencies. Keep the advertised library version within
the metadata's range, or update that entry in META-INF/jarjar/metadata.json and the
matching Wolfism dependency range if your compatible build uses a different version.
No proprietary signature or encryption prevents replacement. Wolfism's source is
also supplied in the project so it can be rebuilt against replacement libraries.
For LowDragLib2, preserve or replace its own Kotlin/Taffy nested dependencies and
corresponding notices as appropriate. Runtime artifacts are not guaranteed to be
byte-reproducible when rebuilt with different toolchains; recorded hashes identify
the original distributed binaries, not a requirement imposed on modified versions.
